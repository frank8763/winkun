# T264：首48条离线精确重建与梯度诊断

这是已有数据的有界诊断，不是新导航训练，不为T263延长预算。T263继续按其原协议运行；本诊断仅访问其事先锁定的首48条完整训练payload、前两轮updates固定前缀及注册源。任何新追加记录都不进入分析。

问题：已有正例未转为确定性成功，是否伴随任务梯度相互抵消、旧软保持项占优，或原生保持检查只能接受很小的步长？左侧无到达的组是否只有失败时间差所产生的相对回报信号？这些是可区分假设，不提前认定某项是唯一根因。

从T255安全父模型和fresh Adam在RAM中精确重建前两轮8个既有更新，逐项要求与原记录的提案报告、Actor和Adam哈希完全一致；接受查询只能查原记录中完全相同policy hash的已知20例结果，未知hash立即拒绝。明确计8次历史克隆优化器调用，新增导航RL更新为0，不把重建算新证据。任一精确性断言失败即停止诊断，保留错误，不以容差放宽代替重建。

在真实r0/r1/r2行为策略上计算四任务损失梯度余弦、PCGrad前后范数、旧软保持梯度相对范数、每任务与总方向的内积，结合每固定reset四条完整MC回报及成功/碰撞/超时标签。局部导数只解释本批随机策略代理目标；单位SGD方向的符号不等于Adam效果，更不等于确定性闭环改善。负余弦本身不能证明该改PCGrad，也不能由旧20例安全推出旧275安全。

上限180秒、1MiB输出、0物理、0模拟器/worker/新采集/新原生验收/模型导出；最多8次仅RAM克隆Adam调用。单线程并绑定可用最后一个CPU，避免占用当前0–4号训练CPU。保留T263完整64MiB预算后，再预留T264完整1MiB仍小于global1GiB，空闲盘至少40GiB；实际容量计算在protocol。代码提交、真实首16行为密度与48份payload零优化器预检通过后唯一执行，不重跑/不加数据前缀。

依据[PCGrad原论文](https://papers.neurips.cc/paper_files/paper/2020/file/3fe78a8acf5fda99de95303940a2420c-Paper.pdf)检查冲突及梯度支配；本文仅沿用其诊断思路，未测曲率、未验证其理论条件，不是算法改进实验。反向起点课程也有[既有工作](https://proceedings.mlr.press/v78/florensa17a.html)，但本项目历史T171的起点课程未解决原任务，不直接重复或把它包装为新贡献。

结果只用于T263结束后的下一机制决策；不会改活动协议、触碰Phase、向Actor接新Critic或启动七米/八米。
