# T717 primary review: acquire conditional recovery before consolidation

Reviewed 2026-11-24, Stage only. This is a literature/source review and implementation recommendation, not registration, a launch, a result, or permission to extend a deadline. No native simulation, training, optimizer update, or historical output mutation was performed for this review. New authorization communicated for this design: learning stops 19:30, native 20:15, all work 21:00 Beijing, with each registered earlier deadline binding.

## Decision

**A bounded, fresh-data PPO experiment on learner-induced recovery conditions is scientifically admissible; success is unknown.** Use the frozen B0 neural backbone with a trainable full residual MLP, an independent freshly initialized state-value MLP, iid clipped Gaussian exploration, and PPO/GAE on fresh learner-controlled suffixes only. Carry the learner's own recurrent state through the entire actual prefix. Phase 1 has no old-task imitation, projection, retention penalty, or old-task acceptance/rollback gate. Preserve T698 separately; acquiring an experimental recovery policy does not replace it.

The PPO paper alternates collection by the current frozen behavior policy with bounded optimization epochs, then refreshes the behavior policy. Its clipped surrogate is an optimization heuristic, not proof of safe recovery or global policy improvement. This application is an engineering adaptation of an established algorithm, not an algorithmic novelty claim. [PPO, Sections 3 and 5, Algorithm 1](https://arxiv.org/pdf/1707.06347).

T716's full fixed recovery panel was 5/18 safe, with 1 collision and 12 timeouts, despite nominal original-start teacher successes, with zero learning. Thus parameter-update forgetting cannot explain that diagnostic failure. It motivates acquiring recovery capability on these conditions; it does not establish that PPO, a frozen representation, or a larger head will solve them. Do not select only T716's five successful cases for training or qualify their complement by new teacher/seed/takeover searches. Local evidence: [T716 NEXT_DECISION](../t716/NEXT_DECISION.md), [current RESEARCH_STATUS](../../RESEARCH_STATUS.md).

## What is on-policy here

Let `k` be the fixed takeover decision. Replaying B0's prefix and reconstructing the student's own hidden state defines a **conditional recovery reset distribution**. B0's executed prefix actions are exogenous history. They are not samples from the updated learner, even when the learner is evaluated on those inputs. Mask every prefix decision out of policy loss, GAE, advantage normalization, value loss, entropy, KL statistics used for PPO stopping, and sample counts advertised as learner interaction. Native prefix replay still consumes real physics and budget.

After takeover, collect every suffix action with the same frozen current learner and declared exploration distribution; retain failures, collisions, and timeouts. Store behavior model hash, actual prefix and suffix observations, executed previous-command inputs, before/after hidden states, stochastic/ownership masks, raw actions, atoms, log probabilities, native durations, rewards, terminal flags, and final observation. Compute frozen old log-probabilities/values/advantages before updates. Do not update during collection or reuse an earlier policy's suffix as fresh on-policy data. Multiple PPO epochs may reuse the one just-collected batch; the next round requires a fresh batch. These demands follow Algorithm 1's sampling/optimization split; the recovery reset interpretation is our explicit application, not a theorem in PPO. [PPO Algorithm 1](https://arxiv.org/pdf/1707.06347).

Conditional recovery evaluation must use the identical fixed prefix and remaining original horizon. It is not autonomous original-start navigation. A frozen learner evaluation from the original start is a separate score, with the learner controlling every action. There is no deployed teacher, history lookup, task-ID selector, router, planner, or waypoint policy.

The actual inherited core is `torch.nn.GRU(128,64)` with `batch_first=False`; `[T,1,128]` means T time steps in one sequence. This is documented by the local T446 implementation and explicitly checked in T417. The early reset allegation was incorrect and must not be used as a diagnosis. [T446 Actor](../../../experiments/t446_plain_joint/t446_learning.py), [T417 preflight](../../../experiments/t417_representation_adaptation/prepare.py).

For T717 prefer an unambiguous `q.step` replay from `h0=0`, feeding every actual raw120 prefix observation and the actual preceding float32 command. Do not import B0's hidden state as the student's hidden state. At takeover the prefix is neither forgotten nor counted twice; no reset occurs there. Match batch-sequence outputs and literal row-loop features/locations/hidden states with the deployment arithmetic before admitting training. Official Baselines also treats recurrent hidden state as explicit carried state, provides episode masks, and batches whole sequences rather than arbitrary shuffled time steps. [Baselines recurrent model contract](https://raw.githubusercontent.com/openai/baselines/master/baselines/common/models.py), [recurrent minibatch branch](https://raw.githubusercontent.com/openai/baselines/master/baselines/ppo2/ppo2.py).

Frozen encoder/GRU features can be detached and cached for these recorded histories: the head does not change their recurrence on a fixed input tape. This is a recurrent deployed policy with head learning, not learned-memory acquisition or full-GRU PPO. Local T665 already uses a separate `184→64→1` Value over detached causal features; T651 is terminal-outcome clipped episodic PG rather than the proposed reward-to-go/GAE experiment. Reusing its runtime/audit plumbing does not make the algorithms identical. Training the GRU is not technically necessary for valid head-only PPO. If a later design trains it, every policy likelihood must reconstruct the current policy's hidden state from the actual full history; cached old hidden states then cease to be exact current features. Detaching a burn-in prefix is a disclosed truncated-gradient approximation, not full-history BPTT. Do not silently turn on GRU learning in this fixed head-capacity pilot after observing failure.

## Action likelihood: preserve the sampling measure

Official Baselines' diagonal Gaussian samples an unbounded raw action and computes a Gaussian likelihood at that sample. It does not justify evaluating a Gaussian density at a clipped command. [Baselines DiagGaussianPd](https://raw.githubusercontent.com/openai/baselines/master/baselines/common/distributions.py).

Two coherent choices are available; fix one before collection. (1) Store the raw Gaussian sample `u`, execute `float32(clip(u,-1,1))`, and compute both old/new Normal log densities at the same `u`. This is a latent-action policy; KL/entropy are latent statistics. (2) Preserve the repository's iid censored law: normal raw density in the interior and Gaussian tail masses at boundary atoms. T441's `EDGE=(1+nextafter_float32(1,0))/2` accounts for values that round to executed ±1; lower/upper atom log masses use `log_ndtr((-EDGE-mu)/sigma)` and `log_ndtr((mu-EDGE)/sigma)`. Interior raw samples remain retained latent variables, so this is a coherent mixed sampling measure without pretending the rounded interior command has continuous density. [Local density and EDGE](../../../experiments/t441_joint_actor_critic/t441_learning.py).

**Recommended for compatibility: retain option 2 with sigma=.2 iid and actual atom/raw generation.** Re-export the initial exploration variant and policy hash separately from sigma=.05 parent weights; identical weights do not imply identical stochastic policy. Preflight old/new log-probability equality and ratio≈1 before any update, exact interior/positive/negative atom classification, two-dimensional summation, and finite tail gradients. Apply PPO clipping to the ratio, not the log probability, raw action, or advantage. Never score a teacher action as learner-on-policy by manufacturing its Gaussian probability. Exact float32 execution must match native replay; training/inference dtype and normalization must match too.

Do not retain temporally correlated AR noise accidentally. If `u_t=mu_t+rho*(u_{t-1}-mu_{t-1})+sigma*sqrt(1-rho²)*epsilon_t`, the conditional mean and likelihood depend on `mu_{t-1}` reconstructed under the candidate policy on the same history. IID marginal Normal scores are wrong; evaluating only the old residual is wrong. Boundary collapse also requires care if the future generator retains unclipped previous raw action. Reset/noise-state and initial-noise laws must be specified. These are elementary conditional-density consequences, not an AR-PPO result claimed by the paper. The minimal pilot uses rho=0 and avoids this extra latent-state contract.

## Value, GAE, time, and stopping

Use independent `184→64→1` Value parameters/optimizer, detached frozen causal features, no sampled current action as input, and no Value gradient into the Actor. Build old values before fitting the current block; freeze GAE/returns throughout its PPO epochs. Value estimates are baselines, not a Q planner or action chooser. GAE explicitly trades value-error bias against variance; a lower fitted Value loss is not evidence of successful navigation. [GAE, Equations 16–19](https://arxiv.org/pdf/1506.02438).

At each suffix transition with native duration `n_t`, use `Gamma_t=gamma_native**n_t` and the already declared intra-hold reward aggregation. With decision-scale lambda=.95, `delta_t=r_t+Gamma_t*b_t*Vold(next_t)-Vold(t)` and `A_t=delta_t+Gamma_t*.95*c_t*A_(t+1)`. Do not silently use `.95**n_t`; that would be a different trace time scale. Freeze reward semantics and report the native gamma and resulting physical horizon. Hand-check one short mixed-duration fixture against an independent loop. GAE's temporal-difference construction is primary evidence for the recursion; duration adaptation is this experiment's explicit semi-Markov implementation choice. [GAE](https://arxiv.org/pdf/1506.02438).

Declare task-horizon expiry a genuine finite-horizon failure: GOAL/contact/boundary failure/true horizon end have `b=c=0` and zero bootstrap. Confirm that the raw120 clock provides the relevant remaining-time information after the prefix; the original horizon is not restarted at takeover. A collector-only cut before task termination has `b=1,c=0`, bootstraps from the true final observation and matching carry, and is not a failed task. A process killed without that observation is censored and not a complete training trajectory. Never bootstrap from an auto-reset observation. Time-limit semantics depend on whether time defines the objective or merely limits data collection. [Pardo et al., Time Limits in Reinforcement Learning](https://proceedings.mlr.press/v80/pardo18a.html). Baselines' old runner combines done masks in GAE and its DummyVecEnv resets immediately; copying those interfaces blindly can lose the needed final observation. [Baselines runner](https://raw.githubusercontent.com/openai/baselines/master/baselines/ppo2/runner.py), [DummyVecEnv](https://raw.githubusercontent.com/openai/baselines/master/baselines/common/vec_env/dummy_vec_env.py).

## Minimal bounded implementation and interpretation

Concrete recommendation communicated by the coordinating agent: freeze complete B0 parent; train only the 20,198-parameter full residual MLP plus fresh Value; fixed hashed 12-training/6-holdout split of the original 18 conditions; at most 3 rounds × 2 stochastic suffix episodes × 12 training conditions; at most 4 PPO epochs and 4 Value Adam steps per round, with separately counted live/shadow/independent work. Use declared native rewards, duration discount, decision-lambda=.95, iid sigma=.2 and terminal horizon convention above. Every holdout is untouched by optimizer/early checkpoint selection; all 18 are already exposed recovery conditions, so these six are held out from T717 updates, not globally unseen tasks. One fixed training seed is a pilot, not independent replication. These exact limits belong in the coordinator's immutable protocol; this review does not register them.

Log per-round suffix outcome counts and per-ID frozen deterministic recovery, contact, timeout, remaining distance, native steps, ratio/KL/clip fraction, gradient norm, Value error, update counts, and wall deadlines. Select the predeclared final budget state; do not mine successful exploration samples or intermediate checkpoints to announce deterministic capability. Exact replays and shadow reconstruction validate implementation, not additional independent successes. Run original-start evaluation only as explicitly budgeted, and report it separately. Phase-1 acceptance does not depend on old-task retention; consolidation is subsequent work only after a fixed acquisition criterion is met.

Concrete negative evidence from independent primary research: Engstrom et al. show implementation augmentations can account for much of PPO's benchmark advantage, so a new head/likelihood/reward-time-scale package cannot establish which component caused a change. Ilyas et al. find mismatches between surrogate improvement, true return, and learned Value quality. Therefore even a numerically correct PPO update and improving surrogate are insufficient; frozen native closed-loop outcomes remain the evidence. [Implementation Matters](https://arxiv.org/abs/2005.12729), [A Closer Look at Deep Policy Gradients](https://arxiv.org/abs/1811.02553).

Progress & Compress motivates separating new-task progress from later consolidation; it already uses an active component connected to a knowledge base followed by compression. This is conceptual motivation, not novelty or an exact reproduction of that method. [Schwarz et al., ICML 2018](https://arxiv.org/abs/1805.06370).

**Blocking conditions before launch:** inability to reproduce owncarry/locations/likelihood before updates; mixed or wrongly scored clipping/AR laws; prefix included as learner-on-policy; mismatched precision/clock/remaining horizon; insufficient reserved time/storage for the entire collection–fit–verification path; or any outcome-dependent teacher/seed/takeover search. No primary source proves the frozen features can express successful recovery, that three rounds suffice, or that these fixed tasks generalize. A failed bounded pilot must remain a failed/unfinished pilot, without automatic seed search or budget extension.
