## What PPO changes—and what it does not

[PPO, 2017, §§3/5, Algorithm 1](https://arxiv.org/pdf/1707.06347) clips **per-decision probability ratios**, optimizes a fixed collected batch for finite epochs, then collects under the updated policy. Clipping is a surrogate optimization device; it does not impose a hard parameter trust region or a guarantee for every deterministic task. Old behavior likelihoods must remain fixed within a block. Clipped-Gaussian commands require the actual mixed distribution: boundary atoms use Gaussian tail probability, interior commands use density. A Gaussian density evaluated at a clipped boundary is wrong. This last requirement follows from the declared action distribution, rather than being a PPO-paper implementation claim.

[GAE, §3 Eq.18 and §6 algorithm](https://arxiv.org/pdf/1506.02438) gives, at gamma=lambda=1 and true terminal absorption, `A_t = Y - V(h_t)` for terminal safe-GOAL indicator Y. This is Monte Carlo credit with a learned state/history baseline; it supplies no bootstrapped temporal-credit advantage over terminal-return PG. The paper explicitly updates the actor using the previous value function before fitting the next value function, warning that fitting first adds bias. Existing T655 already used per-decision ratios; do not present those as new. The substantive changes are fresh original-start joint batches after every block, cleaned references, and a frozen learned baseline replacing terminal peer-LOO.

Use previous-block V, with block-zero V fixed in advance. Cache detached predictions before actor proposals; freeze the complete predictor, including any shared feature computation. Fit V to current complete-episode Monte Carlo labels only for the next block. A previous-policy baseline can be inaccurate yet action-independent; it may increase variance. Same-batch fitting followed by immediate reuse is not justified merely by detaching tensors. An alternative requires splitting **whole independent trajectories**, not timesteps. These are estimator-design implications, not evidence that Stage's new baseline reduces variance.

No Q estimates, action derivatives, or value-based acceptance are needed. Log held-out value error and gradient norms by task; aggregate value MSE alone cannot establish variance reduction. Gamma=1 matches the declared terminal stochastic objective. Zero entropy bonus still leaves stochastic-training versus deterministic `clip(mu)` deployment mismatch.

## Causal recurrent and weighting contract

[R2D2, ICLR2019](https://openreview.net/pdf/387fb2fcee8f74c53cf707a9856f40c458f33933.pdf) identifies parameter lag, representation drift and recurrent-state staleness. Reading scope here: indexed published abstract/introduction; direct PDF retrieval met a browser challenge, so no appendix or implementation audit is claimed. For this experiment, recompute current-policy hidden states causally from episode reset over the entire recorded history. Stored old-policy carries cannot substitute in numerator likelihoods after trainable recurrent inputs change. Full-sequence differentiation and valid masks must exclude padding; original scene, goal, initial observation, integration and remaining-time contracts need preflight checks.

For BC, first average valid decisions within each task, then average 387 unique task IDs: one canonical successful reference per ID. For terminal RL, average task-balanced **episode sums**, with a common fixed scale such as 512. Dividing each episode by its realized length changes the terminal-success objective. Do not select only successful fresh trajectories or reject batches because they lack mixed outcomes without declaring the resulting selection bias. Administrative truncation is censored, not terminal Y=0.

## Nearest baselines and acceptance

[CLEAR, NeurIPS2019, §3](https://arxiv.org/pdf/1811.11682) combines fresh experience, replay, behavior/value cloning and V-trace correction for off-policy RL. Fresh PPO plus old-action BC is a relevant simpler control, not a CLEAR reproduction. Historical references belong in the supervised retention term, never silently in on-policy PPO. [C-CHAIN, ICML2025](https://proceedings.mlr.press/v267/tang25g.html) is verified precedent for reducing output churn; publication abstract checked here, author implementation only in the earlier local audit. Tail weighting, adapters and replay do not independently establish novelty.

Predeclare tail size, task-loss aggregation and tie rule. Match PPO mean/tail arms on fresh task distribution, epochs and native proposal allowance; after branches diverge, later trajectories differ and are not paired samples. Distinguish mean-versus-tail **loss** from full-policy rollback: changing both together confounds attribution.

For every proposal record each tested original-start outcome, lost/gained IDs, native cost, actor/Adam state and rejection reason. Roll back actor **and** optimizer on rejection. Screens used repeatedly for selection are development evidence. Promotion requires the declared complete 407 evaluation, all 387 required successful IDs, original deterministic control, and saved/reloaded reproduction. The 387 reference union contains acquisition targets as well as historical T501 successes: define intermediate commit rules separately so an all-targets gate does not forbid incremental learning.

Scientific failure of one fixed branch should advance to the next scheduled branch, not extend its steps or tune seeds. Scene/density/history corruption or resource-bound violation stops the affected root for evidence preservation. Reserve time for full evaluation/audit; missing tests remain null. All-zero successes, repeated rollback, or improvement only in noisy rollouts are useful negative outcomes, not reasons to expand the budget. If replay/tail control matches the new mechanism at equal native cost, added complexity has not earned its place. Finite same-map success is neither generalization nor a safety certificate.
