# Stage：端到端策略的实车可行性与完成条件

2026-11-06。仅 Stage，一手论文核验及工程建议；未启动仿真、训练或实车，没有修改实验协议、源码、模型或runs，未执行Git操作。以下路线不是新实验注册，也不预设车辆转向形式、传感器型号、ROS 版本或计算设备。

**可以把端到端学习策略训练后部署到轮式实车，已有论文实例；当前 Stage 尚未证明具备这一部署能力，更不能保证顶刊。** LiDAR＋相机具备研究条件，但设备数量不构成创新。应先补齐单策略闭环与迁移证据，再围绕一个可检验的机制建立贡献。

## 当前证据边界

[T397](T397_FINDINGS.md)只有同一冻结学生在既有实际偏离态接受4秒外部纠正后到达的证据，包含53秒成功参考前缀，不能算从原起点自主六米。T398实际完成200次监督预热；候选旧八为7/8、一次接触，按门槛拒绝并整Actor／Adam回退，**RL实际执行0轮／0次**。回退后旧八8/8，原起点左右中心1/2，完整54／275／16fresh／78均未安排，稳定门为false。不得把[计划](T398_PLAN.md)中的两轮RL写成已完成，也不得把回退后的保持当新学习收益。依据：[T398实际最终报告](T398_FINAL_REPORT.json)。

## 原论文能支持什么

| 一手来源 | 真实支持与限制 |
|---|---|
| [Tai等，IROS 2017，§III-C、IV-B](https://arxiv.org/pdf/1703.00420) | 稀疏LiDAR、相对目标及上一动作→连续线／角速度，仿真从零RL，迁移到Turtlebot；实机按多个编号目标依次执行，Env-1模型实机失败。使用AMCL提供相对目标所需定位，不能称无定位或任意单目标长程已解决。 |
| [Chiang等，AutoRL，RA-L 2019，§III-B、IV-F、V、附录C](https://arxiv.org/html/1809.10124v2) | LiDAR→连续速度策略有Fetch实机P2P，起终点约13.4米；80.6米为外给路点的PF，排除出无路点证据。P2P依赖定位，有局部导航限制；论文处理传感器、定位及执行噪声，并观察到实机延迟造成更多转向。 |
| [Pfeiffer等，RA-L 2018，§III、IV-D、表II](https://arxiv.org/pdf/1805.07095) | 训练期规划器示范＋BC＋CPO，部署单策略，有仿真到实机证据。最佳c1000+CPO五次路线零碰撞／零摇杆救援，其他模型有干预或碰撞；主方法不是从零纯RL，实机也是目标序列。 |

因此“部署观测到动作的单Actor”与“训练完全不用示范／特权奖励”是不同要求。上述三篇已覆盖端到端轮式迁移，单靠“PPO＋循环网络＋相机融合”不能声称原创；更完整接口比较见[既有文献核验](END_TO_END_NAVIGATION_PAPERS.md)。

## 应先锁定的实车接口

以下为基于论文限制与本项目证据提出的工程建议，尚未实测。

- **动作与动力学：**查清实车接收的是轮速、线／角速度、油门／制动还是转角／速度；与模拟器drive／steer的单位、符号、饱和、更新频率逐项对应。若为转向轮车辆，不能照搬差速车可原地转向的动作。测量轴距、车体包络、最小转弯半径、加减速、制动、转向死区、摩擦、滑移及指令延迟；先用有界校准数据拟合，再确定随机化范围。低层执行器伺服可保留并如实说明，不能暗含路径规划。
- **传感器与时间：**核验LiDAR量程、角分辨率、FOV、安装高度／盲区、无回波编码、噪声／丢帧；相机内参、畸变、外参、曝光和LiDAR对齐。记录采集时间戳、同步误差、传输／推理／执行延迟及抖动，校准策略历史长度、hidden重置和上一动作到底表示指令还是测量。网络前向耗时不能代替完整闭环延迟。
- **真实可用输入：**审查全部120维与历史构造，逐项说明实车来源。相对最终目标必须来自声明的定位／里程计／GPS等可用估计并注入其误差，不能默用仿真真值位姿、障碍几何、未来状态或教师轨迹。定位信息与无运行时路径规划可以并存，信息权限须明确。
- **任务可达性：**按真实车体包络、转弯能力与制动距离确认测试通道和目标可达；先对齐地面、障碍高度及感知范围。几何可达不保证当前策略可达，仿真接触模型也不能替代实车测量。

## 按科学里程碑推进，而非承诺日期

| 阶段 | 进入下一阶段所需证据 |
|---|---|
| A．先完成仿真闭环 | 冻结单Actor，从episode zero、仅最终目标、无参考前缀／教师接管，完成预注册当前任务与旧能力门；再用独立地图、起终点及训练随机种子检验泛化。开发集与被反复消费的恢复态不能当留出。精确重放只验证重现，不增加独立样本。 |
| B．并行实车校准 | 在A推进时可先做传感器日志、标定与有界执行器辨识；核对相同场景的观测／响应差异。依据实测误差更新迁移评估条件，训练集与留出实测条件分开。不必等仿真研究结束才发现接口不匹配。 |
| C．日志回放与影子模式 | 冻结模型，先离线回放，再在车辆由人工控制时仅记录模型输出、不让模型驱动车辆；验证输入合法性、时序、端到端延迟、输出边界与失联停车。离机影子通过后，还须在实际部署计算链复核。影子模式不能证明策略闭环成功。 |
| D．受控低速闭环 | 封闭空旷场地起步，再固定障碍、狭窄通道及预注册新布局；有独立急停、看护操作员和明确接管条件。监督系统只停止／接管，不替Actor算路径；每次急停／人工干预单列，不记为自主成功。停止距离和速度上限由实测确定。 |
| E．论文级迁移验证 | 冻结协议后，跨布局、障碍、照明、地面、定位误差和传感器故障条件评估；报告自主成功、碰撞、超时、干预次数／距离、最小间距、完成时间、路径长度及延迟分布与不确定性。不要只挑成功视频。 |

每轮仍须单独有界注册，不自动追加种子／预算。报告智能体决策数、原生积分物理步、仿真时间、真实运行时间、训练／验收／教师／精确重复计数；不同论文的frame不能直接按本项目500Hz物理步换算。当前资料不能据此承诺多少天训练完或多少天上车。

## LiDAR与相机如何形成研究问题

**建议先把LiDAR单策略和实车校准做扎实；只有相机提供了可复现的新增失败信息，再引入融合。** 例如扫描平面看不到的障碍、语义禁行或局部几何歧义，需要先用配对数据确认，不能凭设想给当前失败归因。端到端融合本身可行，但新输入会改变训练与部署契约，需另立协议，不能塞入T398续跑。

若选择融合，应比较LiDAR-only、camera-only、融合，并匹配训练数据、预算、容量与动作／目标接口；同时测正常、单模态缺失、噪声／遮挡／污染、时间错位及未见故障组合，报告完整推理链延迟。随机删模态是否提升可靠性、模型是否真正使用相机，都需留出消融；性能增加不能直接归因于“融合机制”。

较有价值的候选问题是：**局部纠正训练如何在保留旧能力的同时，提高无接管策略对真实分布偏移的恢复能力？** 这只是待检验假设，不是已确认创新。需同父模型、同新数据与预算的无预热／辅助监督／真实PG对照，多个独立训练种子，未见地图及实机条件；把PG与辅助项的实际作用分开。先解决T398暴露的旧能力退化，再谈扩大场景与融合。上述三篇不是穷尽的新颖性检索，提交前仍需围绕最终机制核对最近一手近邻；任何顶刊录用均不能保证。
