## 对 Stage 的判断（项目推断）

**下一机制应优先检验覆盖闭环状态的 rehearsal 与行为蒸馏，并用实际成功集合决定接受。** CLEAR 给出了最接近“单个无需任务身份的策略”的已有依据；本项目的关键差异是动作误差会改变后续状态与 GRU 隐状态。因此应检验状态覆盖及闭环反馈，而不能继续只把平均离线误差下降当作能力保留。

1. **保留的是成功行为及其因果序列。** 固定 T550 对应 23 项的参考成功轨迹、输入/动作契约和哈希；按任务均衡复习，避免长轨迹支配平均损失。realGRUcarry 下以完整历史或经过核验的 burn-in 重算学生隐状态；不能直接把教师 hidden 塞给学生，也不能把散点观测 BC 当成完整递归行为保持。
2. **纳入学生实际会访问的状态。** 仅旧教师轨迹上的动作保持仍有覆盖缺口。若另立有界训练协议，可加入学生真实 rollout 中的偏离状态及已验证恢复序列；恢复教师必须先从匹配物理状态、原时钟、历史和执行器状态真实成功，才能把相应动作作为纠正数据。T568 接管成功仅说明那次混合恢复可行，尚未证明学生学会。离线训练阶段使用参考策略，部署仍只运行学生 Actor。
3. **保持损失与接受条件分工明确。** 行为蒸馏可用动作回归或有完整密度契约的策略 KL；旧经验若参加 RL，必须明确 off-policy 估计，不能直接冒充新 on-policy 数据。此处不要求引入未经验证的价值函数。任务均衡、序列复习、学生访问状态纠正均是待验证设计选择，不是 CLEAR 已在 Stage 证明的结果。
4. **逐项检验有限成功集合。** 预先冻结参考集合 \(S_{ref}\) 为 T550 的 23 项；候选在相同初态、时限、接触/GOAL 条件、观测和动作映射下测量。接受至少要求 \(S_{ref}\subseteq S_{cand}\)，并在预声明目标中新增至少一项成功；先恢复 T562 丢失的两项，不能用别处新增抵消旧项丢失。报告逐例 `保留/丢失/新增/未测`，未测就是未验证。该集合已用于开发，全部保住仍不是未知场景泛化；独立留出另报。

这与重新扩大旧 loss 权重或再投影一次的区别，是把“实际访问状态及递归历史是否覆盖”作为明确假设，并把每一项原生闭环结果作为接受依据。它仍可能失败：参考动作在偏离状态可能无效、蒸馏目标可能冲突、容量不足或闭环敏感性都未被本次调研排除。

## 两个不能混淆的保证

**EWC 只保护近似重要参数。** 它的目标没有直接约束每条旧任务的原生 GOAL；对角局部曲率也没有表达整个递归控制系统的长期状态漂移。因而“EWC 单独不足以证明逐项保持”有方法层面的理由，但尚不能写成“本 Stage 已实测 EWC 无效”。

**冻结旧网络再追加无路由残差，只冻结了旧部件。** 若部署动作变成 \(a_{new}(h)=a_{old}(h)+r(h)\)，新残差会在旧任务上改变动作，继而改变物理状态、后续观测与 hidden；旧权重不变并不使组合策略函数不变。要得到 PNN/PackNet 式旧函数保留，需要不受新分支影响的旧输出路径及正确选择机制；这与当前无任务路由约束不一致。对有限存档状态令残差为零，也只约束这些点；除非证明整个旧闭环访问域及状态更新都保持，不能声称精确保留所有旧任务。

本页只提出下一有界协议应检验的机制与接受规则，不启动训练、仿真、参数网格或历史实验重跑。
