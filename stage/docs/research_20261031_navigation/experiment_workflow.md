# 后续Stage实验的文献与实现检查

用户于2026-10-31明确要求后续实验也主动检索解决办法。该要求持续有效，不需要每轮再次询问。

每个新实验在注册/启动前完成：

1. 写明当前要排除的失败机制，引用本项目已存原始证据；区分已证实的问题和推测。
2. 围绕新变量检索近期与基础论文、作者代码/正式基准，同时找支持与负面/相反结果。优先一手来源，记录论文版本、检索日期、查看范围与可访问限制。不能声称穷尽全网或把摘要当全文。
3. 核对传感器、车体/动作、决策/物理时标、奖励/终止、历史长度、训练样本与更新次数、地图/规划器/教师依赖、评估划分是否匹配。机器人不同或使用了额外信息必须说明。
4. 明确采用/改写/排除/暂缓哪些方法，为什么；若用作者代码要记录版本/许可证。项目已有失败的同类方法不可换名字重复启动。
5. 制定共同基线和单因素对照。若同时更换多项，只能作为工程pilot报告，不将组合结果归因于某一个模块。写出失败会否定什么、不会否定什么。
6. 代码、输入SHA256、训练/诊断/重放/评估计数、墙钟、物理步、输出与临时归档最坏字节数锁定后才启动；最终验收留独立时间。所有newruns硬上限1GiB、空闲盘>=40GiB，不能用磁盘足够就静默扩预算。
7. 新Actor/Value/分布和时序模块先检查真实动作、密度、梯度、因果性、重置、time-limit/collector-truncation区别与初始函数；这些检查不等于导航成功。新Q/风险/进度辅助必须先验证留出真实效果，再引导策略。
8. 所有到达、接触、超时、删失都保存；缺测不计失败，更高代理回报不计成功。先完成原始5m、旧任务、保存重载与局部鲁棒性，再进入独立留出/更长距离。
9. 仅靠CNN/GRU/注意力/奖励/安全头等已知模块堆叠不宣称原创性；创新点必须另查最近工作并有相应消融、多种子和跨场景证据。

始终Stage only，部署单神经Actor从局部观测到原生执行动作，无外部规划器、人工路点或运行时教师；历史Phase命名的已验证模拟器依赖不等于允许使用Phase研究。
