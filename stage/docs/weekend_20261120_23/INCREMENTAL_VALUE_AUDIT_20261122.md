# 相对普通插值和回放BC，实际多解决了什么？

2026-11-22，Stage限定的只读分析。实验及自动化维持[用户停止状态](USER_STOP.json)。笔记作者只读源码、协议和既有报告；主任务另外对已保存中心/半径做了单核有界离线距离核对，约6.9秒，记录见下。没有策略前向、拟合、训练、native、模型改写、归档、同步或Phase研究访问。下面的对照只是待重新授权的方案。

**现在能支持的回答：多完成了“完整有限历史上的可验证非干扰”，尚未证明多于普通紧支撑插值，也没有证明其改善值得容量代价。** T501→T698核心成功384→398，新增14个已曝光起点且原成功逐ID保持；这是实际成果。但没有同源、同预算的普通插值/回放BC对照，因而不能将14个成功全部归因某个新机制，更不能把额外存储除以14当作相对基线的成本效益。[T694](t694/FINDINGS.md)、[T696](t696/FINDINGS.md)、[T698](t698/FINDINGS.md)

## 保证来自哪里，哪些并非额外能力

实际代码使用冻结的184维`[自身GRU64, normalized120]`表示，并叠加

`phi_i(z)=relu(1-||z-c_i||²/r_i²)²`，`r_i=.49*min(d_old,i,d_other,i)`，`w_i=target_command_i-parent_location_i`。

源决策逐点成为中心；半径构造及实际算术检查使源中心矩阵逐位I、所有受保护历史上的新增响应恰为0。无基函数激活时`torch.where`直接返回父函数原结果；自身carry、batch1、clip→float32及原生重放验证将代数条件落到执行路径。T696冻结整个T694后追加一层；T698冻结整个T696后追加一层，并以候选自身carry重建跨表示来源，而不导入来源hidden。[T694 owner：basis/location/construction/verify_commands](../../experiments/t694_full_history_compatibility/t694_actor.py)、[T696 owner](../../experiments/t696_existing_success_compatibility/t696_actor.py)、[T698 owner](../../experiments/t698_cross_representation_success/t698_actor.py)

在同一确定性runtime、完整初态、历史初始化、控制时钟和实际命令全部一致的前提下，逐步归纳重现旧轨迹与终态。它比“回放MSE低/漂移小”强：后两者本身不提供命令逐位相同的充分条件。它只保证被覆盖的有限历史，不保证随机策略、未见起点、扰动球或未知地图。对源起点的逐命令复现也主要是履行插值构造，不是训练外预测。[精确命令充分条件及前提](EXACT_COMMAND_RETENTION_PRIMARY_REVIEW.md)

但**普通紧支撑RBF配上相同冻结body、分离支持和执行验证，也有同样保证**。本实现没有发现一种超越插值的额外学习算子；增量主要是把既有局部构造扩展到完整保护集，并验证多来源兼容。T546已有冻结body+局部RBF的直接先例；非干扰与扩容也不是新概念。[T546原始报告](../day_20261114/T546_FINDINGS.md)、[既有一手文献阅读边界](PAPER_PATH_RETROSPECTIVE_20261122.md#一手近邻哪些东西已经有人做过)

若**每一个中心**都有`d_other,i≤d_old,i`，去掉`old`项就得到相同半径、系数和函数；全局最小值比较不足以推出这个逐中心关系。父任务另做了一次保存张量检查（本笔记作者未独立复算），结果提供更具体的区分：[只读几何记录](INCREMENTAL_GEOMETRY_INSPECTION_20261122.json)。

| 层 | `old`项实质缩小半径的中心 | 改为普通`.49*d_other`后，最近保护点进入支持的中心 |
|---|---:|---:|
| T694 | 3/1405 | 0 |
| T696 | 669/1737 | 189 |
| T698 | 28/734 | 0 |

这是保存中心/半径的几何判别，不是闭环结果：在`old`项生效时，`saved_radius/plain_radius=d_old/d_other`，普通支持触及旧点需该比值小于`.49`，而不只是小于1。T698其余少量逐位半径差属于CPU/CUDA舍入量级。故T694/T698的半径虽然有变化，普通规则在这些有限保护点上仍分离；T696才有可检验的额外非干扰作用。189个交叠中心仍不证明命令改变，须排除残差抵消、clip和float32量化。三层均不能由这些距离推断新邻域鲁棒性。该独立检查没有模型前向、拟合或native，原模型SHA不变。[记录及边界](INCREMENTAL_GEOMETRY_INSPECTION_20261122.json)

相对回放BC，当前获得的是一个**通过扩容买来的构造性保留方式**：旧函数完全冻结，新增局部自由度承接源标签。普通BC在同样数据上是否已足够、同样bytes能否做得更好，仍未测。T691R一次固定BC/KL门失败不是BC家族败北，也不能当作本轮匹配对照。当前亦未解决任意失败状态的成功纠偏、两个0/4邻域家族或9个核心失败。[T691R](t691r/FINDINGS.md)、[T698结论](t698/FINDINGS.md)

## 只补一项最小判别：同源、同body的头部对照

选择已有几何区分力的T696，固定整个T694父模型、同403条保护历史（81956决策）和七条既有源（1737决策），完整源SHA、重复冲突规则及自身carry不变；不引入新教师或source。一次实验含以下固定三臂，A可复用已审结果，不重启T696。[原T696定义](t696/PLAN.md)

| 臂 | 唯一比较对象 | 读出存储预算 |
|---|---|---:|
| A | 已保留的T696保护紧支撑插值 | 2,598,552B |
| B | 同中心/系数/算术，仅改`r=.49*d_other`的普通紧支撑插值 | 相同 |

C的bias也计入bytes，与A仅差1480B；这是实用的等部署头部bytes对照，不是同参数化的机制消融。共同父模型不重复扣预算，训练态Adam与回放另计。旧监督为零残差保持父`location`，新监督为同实际源命令减父`location`；按旧、新两组分别每ID均衡取均值。回放权重、优化步数和学习率目前未锁定；不能只沿用历史一次64步失败就声称给了强BC公平机会。正式比较给各方法同等、事前有限的开发配置机会（建议每法最多3个），同时报告预算内拟合质量与验证选择依据，最终测试前冻结配置。T691的64步设置只可作工程参照，不能代替这次公平选型。初始化、loss精确定义、全部数据和硬件需在任何运行前封存；不在最终native测试后改权重/步数救结果。[历史有限BC配置与失败边界](t691r/FINDINGS.md)
