# 后续Stage执行窗口安排

1. 对用户分别报告计划工作量（分支/采集/更新/验收）、依据已测吞吐给出的预计耗时范围、硬截止。只有单个短试验时，明确它做完就结束，不能让两小时上限看起来像两小时已排满的工作。
2. 用户要求无人值守利用整段时间时，实际启动前必须实现并预注册有限接力队列：每项新的可证伪问题、输入/源SHA、预算、成功/失败转移、独立审计、本地manifest、离线可执行性。仅有文字草案不是已落地接力，不能宣布后台会继续推进。
3. 一个分支未过完整门槛，只有事前注册且真正不同的后继机制才可接力。不得重启旧目录、临时加同机制轮数/seed/噪声或借新编号续失败预算。共同证据/数值合同破坏必须停并如实报告。
4. 按实际剩余时间/物理/命令/磁盘预留完整后继最坏预算与验收归档时间；不足时不启动残缺分支。磁盘global1GiB/free40GiB、Phase隔离、单Actor无运行规划器/教师边界不变。
5. 进展以真实完整验收与独立证据为准，不以训练loss、教师或探索成功、更新次数或运行时长替代。队列提前完成、全部有限机制失败或预算触发时报告真实停止时刻、已执行/未执行及原因，不假称仍在跑。有效计算不等于故意等待截止或重复确定性失败。

这份文档约束后续安排，不改写T451已经结束的协议，也不是新实验注册或启动授权记录。
